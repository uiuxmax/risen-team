# Аудит і продовження підготовки випуску — 5 листопада 2026

Перевірено редактор, автозбереження, незалежність залів, API, SQLite,
обмін даними, native-лаунчери та процес складання. Застосовано Bug Hunter
і Superpowers; окремі агенти перевірили сервер, редактор і випуск.

## Виявлені помилки

1. Після `pointercancel` або втрати pointer capture перетягування/зміна
   тривалості залишалися активними. Скасування тепер відновлює початковий
   стан; наступний рух вказівника не продовжує редагування.
2. Експорт залу перевіряв початкове значення autosave із сервера. Після
   вимкнення автозбереження він міг зберегти правки без підтвердження.
   Перевірка використовує живі налаштування редактора.
3. Автоматична назва дубліката могла перевищувати 80 символів. Сервер
   створював зал, який не проходив власний імпорт; діалог дублювання
   надсилав завелике значення. Обидва шляхи зберігають допустиму довжину
   та суфікс копії.
4. Зміни тренерів, типів занять і їхнього порядку не оновлювали дату залу.
   Операції тепер оновлюють дату в межах своєї транзакції.
5. Повторне відкриття macOS `.app` через Finder не повертало браузер.
   Додано AppKit delegate-обробник з перевіркою готовності та завершення.
6. Windows CI падав під час збирання SQLite: `windows-latest` перейшов
   на Visual Studio 2026, яку встановлений `node-gyp` не розпізнавав.
   Обидва Windows workflows використовують `windows-2022` із VS 2022.

## Перевірки

- Початковий повний прогін: 49 файлів, 399 успішних тестів.
- Нові регресії запускаються до та після виправлення. Сценарій справжнього
  Chrome до виправлення завершився `Timed out: cancelled drag rollback`.
- Остаточний повний прогін: 49 файлів, 410 успішних тестів;
  результати — `2026-11-05-tests.json`. TypeScript, ESLint і production build успішні.
- Онлайн-аудит npm: `2026-11-05-npm-production-online.json` — 0 вразливостей;
  `2026-11-05-npm-all-online.json` — 12 moderate у dev-інструментах, 0 high/critical.
  Початкові звіти без суфікса `online` не є повною перевіркою: локальний npm
  був налаштований на `offline=true`. Онлайн-аудит виконано з `--offline=false`;
  результат підтверджено чистим встановленням у CI. Dev-залежності не включені
  до клієнтського runtime; несумісні downgrade, запропоновані npm, не застосовувалися.
- Production HTTP/SQLite: `halls-production-smoke.json`.
- Chrome, взаємодія редактора, дві вкладки, recovery і PNG/PDF/SVG:
  `browser-smoke.json`. Тести використовують окремий профіль та тимчасові проєкти.
- SHA-256 робочих файлів даних зафіксовано до перевірок; робочий проєкт
  не використовується для тестів.

## Продовження попередньої роботи

GitHub-конектор має доступ до приватного `uiuxmax/risen-team`.
У запуску [41824860704](https://github.com/uiuxmax/risen-team/actions/runs/41824860704)
обидві macOS-архітектури вже успішно пройшли тести, складання, перевірку
структури й ad-hoc підпису; пакети записані у приватні чернетки релізів.
Загальний failure належить Windows SQLite, а не macOS. Попередня локальна
документація не відображала цього стану.

Для повторної перевірки виправленого коду native workflow підтримує
явні гілки `release/**` і стандартний шлях перевірочного звіту.
Перед збереженням приватних чернеток на кожній платформі запускається
сервер саме з готового native-пакета та вкладений Node.js. Smoke перевіряє
обмін, незалежність залів, відновлення архіву, SQLite і штатне завершення.

Фактичні системні діалоги, повторне відкриття `.app` через Finder і tray/menu
bar на чистих машинах залишаються ручними приймальними перевірками.
Наявність успішної CI-збірки не підміняє цих перевірок. Пакети залишаються
непідписаними для розповсюдження / ad-hoc для Mac.

Джерела для CI-причини: [журнал Windows](https://github.com/uiuxmax/risen-team/actions/runs/41824860704/job/126556887902),
[образ Windows 2022](https://github.com/actions/runner-images/blob/main/images/windows/Windows2022-Readme.md).
Подія повторного відкриття: [Apple AppKit](https://developer.apple.com/documentation/appkit/nsapplicationdelegate/applicationshouldhandlereopen(_:hasvisiblewindows:)).
